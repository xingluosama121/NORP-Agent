# 20260817 · 库化重构说明

本文对照 `NORP-Agent-mainupdate1.1/`（旧版）与 `src/norpagent/`（新版）的目录结构、功能清单与代码实现，说明本次库化重构的范围与结果。文中数据来自两版源码的实际统计。

---

## 1. 形态与定位

| 项目 | 旧版 mainupdate1.1 | 新版 src |
|---|---|---|
| 形态 | Windows 桌面应用（pywebview + PyInstaller 打包 exe） | pip 库 `norpagent`（MIT，v0.7.0）+ Web 前端 |
| 启动方式 | `python main.py` 弹出桌面窗口 | `import norpagent as np; np()` 一行启动；或 `python -m norpagent` CLI |
| 代码组织 | 35 个 .py 平铺在根目录 | 13 个子包分层（arch/kernel/modes/protocols/...） |
| 代码量 | 62 个 py 文件 / **32281 行** | 86 个 py 文件 / **18497 行**（-43%，文件更多、分层更细） |
| 第三方依赖 | requirements.txt 一大串 | **核心包零依赖**，按需装 extra（openai/anthropic/web/security） |
| 换组件方式 | 改代码 | **注册表 + 预设 + 地址函数**，填名字即可切换 |

行数减少 43%，但能力净增：预设模式、CLI、FLOW 流程编排、9 层 29 钩子、FE 前端模块、mock 模型测试环境均为新版新增。本次重构的实质是把一个整体式的桌面应用拆分为分层库：组件粒度变小、接口显式化，可组合空间扩大。

---

## 2. 定位变化：整体应用 → 分层框架

### 2.1 旧版：整体式桌面应用

mainupdate1.1 的启动链路与主循环均为整体式结构：

- `main.py` 启动 pywebview 窗口，`api.py` 充当 JS bridge，`front.html` 为界面；
- 循环（`loop.py` / `async_loop.py`）、执行器（`executor.py` / `async_executor.py`）、工具定义（`tools.py`）直接写在主程序中；
- 修改行为需修改主程序源码；插件系统（子进程隔离 + 签名 + 审计）仅支持旁挂式扩展，不改变主循环结构；
- 配置存于 `%LOCALAPPDATA%\vibe_agent\config.json`，API Key 存于 Windows 凭据管理器（keyring）。

### 2.2 新版：注册表 + 预设 + 运行时

src 的核心抽象为三个概念：

```
Registry（注册表）── 所有组件按名字登记：模型/工具/会话/沙箱/调度器/UI/插件
Preset（预设）    ── 声明式配置：选定组件组合 + 行为参数 = 一种运行模式
AgentRuntime      ── 通用循环：不依赖具体模型/工具，仅执行「组消息→调模型→跑工具→回填」
```

组件切换通过参数完成，核心代码不修改：`np(model="openai_compat")`、`np(session="sqlite")`、`np(sandbox="pooled")`。

架构层本身被实现为显式规则——`arch/` 子包中的 **ArchLayer + 地址函数 + 槽位**：除底层最小内核（地址解析/注册表/事件总线）外均为槽位，未填地址时走默认逻辑，填地址后替换为指定实现：

```python
np(frontend="norpagent.frontends.console:ConsoleFrontend")  # 控制台前端
np(async_loop="myapp.loop:create")                          # 自定义事件循环
```

旧版中同类改动需要修改 `main.py`，新版通过地址字符串完成。

## 3. 目录结构对比：平铺 vs 分层

旧版根目录 35 个文件平铺，模块边界不显式；新版按职责划分为 13 个子包。

```
旧版（平铺）                              新版（分层）
├── main.py            程序入口          ├── __init__.py      np() 入口
├── api.py             前端桥接          ├── cli.py           python -m norpagent
├── loop.py            同步循环          ├── safe.py          norpagent.safe() 安全入口
├── async_loop.py      异步循环          ├── arch/            架构层/地址/槽位
├── executor.py        工具执行器        ├── kernel/          注册表/预设/Agent/事件
├── tools.py           工具 schema       ├── modes/           4 种预设模式
├── config.py          配置管理          ├── protocols/       7 个组件协议
├── plugin_system/     插件系统          ├── builtin/         内置组件
├── sandbox_pool.py    沙箱池            │   ├── models/      3 个模型适配器
├── vision_*.py (7个)  视觉全家桶        │   ├── tools/       11 个工具
├── norp_safe.py       命令安全          │   ├── sessions/    2 种会话
├── jailbreak_guard.py 越狱防护          │   ├── sandboxes/   2 种沙箱
├── ...                共 35 个平铺      │   ├── scheduler/   2 种调度器
└── capture_worker/    C++ 窗口捕获      │   ├── context/     FTS5 上下文库
                                         │   ├── projects/    项目管理
                                         │   └── ui/          Web 前端资源
                                         ├── hooks/           9 层 29 钩子
                                         ├── loops/           事件循环系统
                                         ├── frontends/       console/headless/web
                                         ├── plugins/         外部插件加载管线
                                         ├── security/        安全组件（解耦）
                                         ├── runtime/         引擎 + 挂载
                                         └── flows/           流程编排内核
```

旧版的组织方式是单层平铺，新版为分职责子包，每个组件可独立替换。

## 5. 实现细节说明

### 5.1 零依赖的实现方式

- 核心依赖：空（`dependencies = []`）；
- 模型：`openai` / `anthropic` 分别安装 extra；未安装不影响注册和列模式，实际调用时才提示；
- 网页：`requests+bs4` 优先，缺失时回落 stdlib 引擎；
- 签名：无 `cryptography` 时签名一律视为「不受信任」——安全姿态不降级，仅更保守；
- Web UI：纯 `http.server` + SSE。

### 5.2 mock 模型

新版 `mock` 模型是注册表中的正式适配器，`minimal` 模式（mock + echo/get_time）构成确定性的基准测试环境，E2E 测试不依赖外部 API。

### 5.3 安全机制的挂载方式

旧版安全逻辑位于 `loop.py` / `api.py`（scan_message 硬编码调用）；新版内核不含安全代码：输入守卫=L3 钩子、提示词加固=L5 钩子，其余策略挂在 `registry.security`。效果为：不加安全时是纯框架，加安全时执行 `safe(reg, level="high")`，安全组件替换不需要改内核。

### 5.4 旧插件的兼容性

旧版 15 个钩子名（on_task_start、before_tool_call 等）在新版 29 钩子体系中同名共存；`PLUGIN_NAME` + `TOOLS` + `execute(tool_name, args, ctx)` 的插件格式原样支持。旧插件加载进新版框架后，安全管线增加了反射绕过检测。

### 5.5 代码量减少的原因

行数减少主要来自去重：旧版同一套逻辑在多处重复实现（loop 与 async_loop、executor 与 async_executor、vision 七个文件中的 HTTP/IPC 封装），新版收敛为「协议 + 一个默认实现 + 槽位」。

## 6. 迁移对照

| 需求 | 旧版做法 | 新版做法 |
|---|---|---|
| 启动 Agent | `python main.py`（桌面窗口） | `np()` 后浏览器访问 `127.0.0.1:8787`；或 `python -m norpagent --mode standard` |
| 换模型 | 设置面板改配置 | UI 设置 / `np(model="openai_compat")` / preset 改 `model` |
| 加自定义工具 | 写插件放 plugins/ 目录，控制面板启用 | 写 `__norpagent_type__="tool"` 的 .py 拖进 /flow，或 `registry.register_tool("name", MyTool())` |
| 订阅生命周期 | 插件里实现 hook 函数名 | `from norpagent.hooks import before_model_call; before_model_call.subscribe(fn)` |
| 安全加固 | 改 config.py 默认值 | `kit = safe(reg, level="high")`，或 preset params 开 `jailbreak_guard` |
| 桌面窗口/托盘 | 内置 | 浏览器化，无桌面壳 |
| 视觉读图 | vision_enabled 开关 | 待 `windows` extra 的视觉插件回归 |

## 7. 数据汇总

- 代码规模：旧版 62 个 py 文件、32281 行、35 个平铺根目录文件；新版 86 个 py 文件、18497 行、13 个子包；
- 钩子：15 → **29**（9 层）；预设模式：0 → **4**；内置模型适配器：1 → **3**（mock/openai_compat/anthropic）；会话/沙箱/调度器/前端：各 1 种写死 → 各 **2~3 种可选**；
- 核心依赖：几十个 → **0**；
- 新增：CLI、FLOW 编排、FE 模块、PTC 模式、项目/长任务工具、FTS5 上下文库、协议层、地址函数。
